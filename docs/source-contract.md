# RequirementsReceiver 来源约定

此服务管理视图引用领取、对象类型解释及审阅资料接收。
当前常规业务使用一个选定来源上下文处理直接列出的记录。目录请求为 `GET /exchange/customer-A`，返回 `customer` 与 `objects`。每个目录成员以 `id`、`href` 提供来源身份与原文位置，原文中的 `object` 和 `customer` 必须与目录一致。

## 记录含义

```json
{
  "object": "R1",
  "customer": "A",
  "type": "requirement",
  "heading": "供电要求",
  "text": "额定供电符合合同条件",
  "editable": true
}
```

这里的字段是来源提供的原始声明，数值文本必须符合十进制规则，不能把空白或未知值转换成零。领域解释保留客户对象身份、编辑权限、需求与证据类型。只有所选范围内且有充分常规依据的记录列入当前收件；其他范围、待确认、历史和冲突分别保留结果，不用覆盖旧原文消除分歧。

## 关联资料与授权查询入口

需求对象、对象关系、枚举定义和原件分别从授权查询入口提供。整份需求清单仍按目录预览；引用对象只沿来源声明的关系与位置定向取得，不为收齐引用遍历对方整个项目。对象关系位置为 `/exchange/customer-A/relations/{id}`：

```json
{
  "view": "V1",
  "relations": [
    {
      "target": "T1",
      "customer": "A",
      "permission": "evidence-only",
      "href": "/exchange/customer-A/views/V1/objects/T1"
    }
  ],
  "definition": {
    "enum": "E",
    "version": "1"
  }
}
```

- `view` 声明关系资料所在视图。部分对象只有在指定视图里才可见，引用目标按来源声明的 `href` 定向取得，目标原文的 `object`、`customer` 必须与关系声明一致。
- 未获准看的引用目标（403、404 等）留下带来源的未解析关系，记录来源对象、视图、目标身份与尝试位置，不补空对象。客户后来开放视图后可再次领取补收：同一身份同一内容不重复产生需求对象，关系观察随之更新为已解析。
- 业务身份由客户上下文与对象编号共同构成，显示名不作身份。两家客户系统使用相同对象编号或同样显示名，记录仍按各自客户上下文分别保管，不能合并。
- 枚举定义位置为 `/exchange/customer-A/definitions/{enum}`，返回 `enum`、`version` 与 `values`（每项含取值 `value` 与显示文字 `label`）。交换过程中枚举定义可能先更新而对象仍使用旧值：定义版本或取值不相容时标注定义缺口并保留来源声明原值，不按显示文字硬转。
- 关系资料未发布（404）只表示该对象当前没有关联资料，不视为业务删除；关系或定义入口暂时不可用会标注观察缺口，本轮不声明收齐。

## 只读证据与回传边界

引用目标本轮一律按只读依据保管，与可编辑需求分开记录，保留来源声明的权限原值。交付审阅人员的结果说明每个关系的来源、目标或定义缺口，并区分可回传修改清单与只读依据；将来回传可编辑内容时，已取得的证据对象不混入其中。

## 本地合作源

`fixtures/source.json` 的 `resources` 是本地来源的 URL 路径到响应正文的映射；只绑定回环地址，不连接真实监管、银行或合作方。原文可通过目录声明的位置取得，关联资料、枚举定义与视图内对象按上述授权入口取得。

`fixtureSource` 支持独立实例、指定路径返回码、一次性来源故障、响应延迟与 `replace` 更新资源；访问记录保留实际请求路径，不凭空生成未收到的响应。测试在进程内操作夹具，不提供对外开放的管理接口。目录不承诺所有关联资料与当前目录同时发布；HTTP 404、403、503 不能自行解释为业务删除。

## 原文和收件

原文字节按 SHA-256 寻址，SQLite 保存来源位置、观察时间、收件范围、业务身份、领域记录、决策与关系观察。收到原文不等于领域接收成功；重复的同一内容不新增收据，同一身份的不同内容不会覆盖原件。`.data/` 仅用于本机数据，演示使用临时目录，运行结束关闭服务并清理临时状态。
